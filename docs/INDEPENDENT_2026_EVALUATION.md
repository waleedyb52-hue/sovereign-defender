| | |

| Format | 30 ModSecurity native audit logs (`modsec_audit.anon.log`), anonymised; SHA-256 of each in `audit/results/modsec_independent_manifest.json` |

**This is not a 2026 dataset.** It is real production traffic from 2025.

**What it can and cannot show:**
- Every request in it was **blocked by ModSecurity** with the OWASP Core Rule Set. It contains
  no benign traffic. So it measures **recall against what CRS blocked on a live server**.
  It says **nothing about false positives**, and precision, FPR, MCC and balanced accuracy are
  undefined on it.
- The label is ModSecurity's decision, not ground truth. Some blocks are CRS false positives,
  and attacks that CRS let through are absent.
- It is a selected sample: the attacks one server attracted in one month.

**Independence checks (done before scoring):**
- Never downloaded or opened before 2026-11-18; no rule in this repository was written from it.
- Exact overlap of the test half with the development files: 0 of 12,949 with
  `fwaf_dev_benign.csv`, and 0 occurring inside `httpparams_dev.csv`. Sealed files were not opened for this check.
- Construction read only section markers, the request line, the body and the rule ids. No
  payload was printed.

**Construction (`audit/build_modsec_independent.mjs`):**
1. 151,845 audit records → payload = request target (path + query), plus `"\n" + body` when
   the log holds a body. **Headers are not sent**: the endpoint classifies a payload, not a
   header set. Every record had a request line.
2. Exact duplicates removed → **25,853 unique payloads** (scanners repeat the same probe).
3. Fixed split by `SHA-256(payload)[0] & 1`: even → **test (12,949)**, odd → **reserve
   (12,904)**. The reserve is not scored. It stays untouched for one later independent check,
   after any change the failure analysis may prompt.
4. Class = the CRS rule families in the record's audit trailer (section H), never sent to the
   classifier. Priority: sqli, xss, rce, lfi, rfi, php, java, generic, session. Records whose
   only CRS hits are protocol, header or scanner rules (920/921/913/911/922) are
   **`non-payload`**. Records with no CRS family id are **`unattributed`**. Both groups are
   reported, not dropped. A payload classifier is not expected to see what these records were
   blocked for.

Test-half composition: sqli 1,159 · lfi 905 · rce 733 · php 128 · xss 75 · java 9 · rfi 4 ·
generic 1 · session 1 · non-payload 5,263 · unattributed 4,671.

### 1.3 Scoring rules (`audit/eval_independent.ts`)

- Code under test: the commit that adds this file. The detector is byte-identical to `5b564ec`
  (PR #3 head); later changes in that commit touch only the web console. Fresh server, fresh database,
  `GEMINI_API_KEY` unset, so the local classifier is what is measured.
- Through the real HTTP server: `POST /api/v1/agent/ai-analyze`, ADMIN key on loopback,
  `x-sd-evaluation-source: 1`, `vector: 'UNKNOWN'`, no `threatScore`. This tests the
  analysis endpoint, **not inline network interception**.
- Each payload sent **once**, no retry, 30 s timeout. Every outcome is kept and counted:
  ok / 413 / 429 / 5xx / other status / timeout / network / unparsable. A failure counts as a
  miss in the headline figures.
- Three decision rules, side by side: the route's verdict (blocks at score ≥ 25 for an
  `UNKNOWN` vector), score ≥ 25, score ≥ 55.
- **Primary figure, fixed now:** route-verdict recall on the payload families
  (sqli+xss+rce+lfi+rfi+php+java+generic+session), with a 95% Wilson interval. The
  `non-payload` and `unattributed` groups are reported separately.
- Scored once. If a figure is low, it stays the result. Any rule written afterwards is
  checked on the reserve half, and that check is labelled as such.

The intervals do not overlap. On production traffic none of the rule work saw, the gain from the
poster baseline is **+23.3 percentage points** on the payload families. SQL injection carries most of it, at +50.1 pp.

Run time for the 12,949 requests was 64.3 s at `2ab323e`, against 5.3 s and 5.5 s for the two
later versions. That is one run each through the analysis endpoint, not a controlled
benchmark, and is **not** claimed as a throughput figure.

### 2.4 What the result says, and what it does not

- **Local file inclusion is the clear gap: 8.29 % in all three versions.** Not analysed yet. One
  candidate explanation, unverified: CRS family 930 also covers requests for restricted file
  names, which carry no traversal sequence. Any rule written for this must be checked on the
  reserve half (12,904 rows, untouched), and that check reported as such.
- **`non-payload` (5,263) and `unattributed` (4,671)** are requests ModSecurity blocked with no
  payload-family rule. Low recall there is expected for a payload classifier that does not
  receive headers. It is reported, not excluded.
- **Labels are ModSecurity's decisions.** Some are CRS false positives; attacks CRS missed are
  absent. A miss here means "CRS blocked it and we did not", not proof of a real attack.
- **No false-positive evidence comes from this set.** False-positive figures still rest on
  HttpParams (0 / 9,664 on the sealed half, in-distribution) and the look-alike tests.
- **This is the analysis endpoint, not inline interception.** Packets were not replayed through
  a network path or through XDP.
- **It is not 2026 data.** The requested 2026 set (Part 1.1) could not be obtained, and no figure
  for it exists.
